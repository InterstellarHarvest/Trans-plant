Each runtime background is a lossless optimisation of its approved source:
pixels under fully opaque room more than 8 px from any visible pixel set to
0; the overlay over it equals the overlay over the source on every pixel at
1536x1024. Savings: Mars -64.6%, Ringed -64.2%, Nebula -65.0%.

4. PROVENANCE AND MAINTENANCE
-----------------------------
All five supplied backgrounds are PMO-supplied generated illustrations (not
NASA imagery); their intake READMEs, manifests and fit scripts are in
source/provenance/. Ringed V2-B differs from V2 in 434 px only (x 872..1128,
y 63..88): the 1x copies of two duplicated stars on dark sky; rings, planet,
sunlight and the other stars untouched. Mars V3 changes V2's rows 0..23
only (the mirrored skylight chevron).
Every step from source to runtime file reruns from source/tools/ and was
verified by MENU-002I to reproduce the committed file byte for byte or pass
its --check (artwork-manifest.json "maintenance" lists the commands):
alpha_variant.py (-> overlay source), optimize_sources.py (overlay, Earth),
make_mars_v3.py (+ find_donors.py), optimize_mars.py, skyfix_ab.py,
optimize_backgrounds.py (Ringed, Nebula); then node tools/build_portable.js.
Note: the MENU-002C2 review branch kept a re-encoded copy (0bfe600b...) of
the Mars painting; the supplied file (dddfe849..., identical pixels) was
recovered from local intake scratch and is the one kept.
The two paintings live in source/paintings/, not originals/: the project
.gitignore keeps every **/originals/ folder off git, and these must ship.

5. ARCHITECTURE
---------------
background-views.js makes ONE draw per fresh page load,
Math.floor(Math.random() * 4) over earth, mars, ringed, nebula (registry
order), and keeps it for the page session: setup's BACK, RECORDS and idling
never redraw or reload; nothing is stored; no player-facing selector. QA:
?view=earth|mars|ringed|nebula|random, ?view=mars-v1|ringed-v1, ?arch=layers.
Renderer (MENU-002C1 B): the background and the overlay are drawn once into
an off-DOM 1536x1024 canvas, exported as PNG (toBlob) and shown in
#title-paint; the canvas is freed. The poster waits for it (at most 4 s).
Recovery only: two aligned <img> layers if the export fails; a background
that will not load falls back to Earth.
Background-specific effects: Earth only has the station, so only Earth has
the three navigation lights (code/background-effects.css, the ruling-113
rules unchanged) and "Departure authorised. Mind the station."; Mars,
Ringed and Nebula have no lights and "Departure authorised. Safe travels."
Poster, CRT power-on, intro, controls, departure and terminal are the same
on every view.
Offline: from file://, disk images taint the canvas, so the overlay and all
four rotation backgrounds come from engine/js/portable_data.js as data:
URLs (tools/build_portable.js; lint_modules fails if it is stale). All four
composite from disk in Chrome and Firefox with the network off; none falls
back to two layers. Over http the bundle is never loaded.
Size and speed: per load overlay 2,074,269 B + one background
952,110..1,029,356 B. Bundle 9,722,406 B (was 7,105,468 B with two views).
Painting ready (median of 5, 960x640): Chrome http 419..477 ms (released
single-painting menu 251), Firefox http 481..501 (250); composite cost
draw 2..4 ms + PNG export 106..159 ms, behind the poster.

7. KNOWN ISSUES (pre-existing, not menu regressions)
----------------------------------------------------
- test_parity_log, Firefox, occasional: a long generated destination name
  (flavor pool "The Promising One (Updated: The Disappointing One)",
  modules/flavor/flavor_pools.json) is shortened in the 120-character
  arrival line and the check expects it whole. Reproduced identically on
  production main 5977981; solo reruns pass (72/72 x5). Gameplay untouched.
- Legacy Google Fonts dependency: index.html still loads VT323 and Press
  Start 2P from fonts.googleapis.com / fonts.gstatic.com (the menu's own
  fonts are self-hosted in resources/fonts/). Where DNS for those hosts
  fails, pages wait on the request and log font console errors in any
  build; this hit local QA intermittently on 2026-10-28.
