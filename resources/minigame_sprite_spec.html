Minigame Design Spec & Sprite Brief
Part 1 — Minigame Design

All minigames fire as a pop-up modal. The modal content swaps per game type. Mouse-only. Target duration 10–20 seconds. Outcome maps to three tiers (perfect / good / poor) which feed the AI quip resolver. All CSS/JS where possible; sprites for backgrounds and key interactive elements.

AI Quip Data Structure

Every minigame shares the same quip resolver. Five AI personalities × three result tiers per game. The resolver picks by state.activeAi. Structure mirrors the existing encounter demo ai_flavor fields — same function, new data pool.

Stop Menu — Active World Verbs
⛏ Mining MINE verb · asteroid / ice field
An asteroid drifts slowly across the screen. Ore veins pulse faintly. Click each node before it scrolls off. Richer veins take two clicks. Some rocks are hollow — click yields a puff of gas and MARV sighing.
Core loop: drift-and-click. Node difficulty scales with crew engineer skill. Hollow rocks are visually indistinguishable until struck. ~12 seconds total.
timing spatial
First implementation step

Build a single scrolling canvas layer with 5–7 circular ore nodes at randomized y-positions. Click removes node and adds yield to a running counter displayed top-center. No skill gating yet — just the core mechanic.

🔧 Salvage SALVAGE verb · debris field
Wreckage drifts past. Some pieces are useful (glowing faintly). Some are dangerous (sharp, red-tinted). Drag useful debris into a cargo rectangle before it exits frame. Drag a sharp bit and hull takes a nick.
Core loop: drag-to-bin before timeout. 3–5 pieces per wave, 2 waves. Useful/dangerous ratio skews by crew morale. ~15 seconds total.
spatial timing
First implementation step

One wave of 4 items drifting left-to-right. Drag-drop target is a fixed rect on the right edge. Wire click-and-drag with mousemove. No dangerous items in v1 — just the drag mechanic and a "salvaged X" result.

🌿 Forage / Hunt / Gather FORAGE verb · region-relabeled
A simple ecosystem snapshot: plants or small fauna appear at random positions, blink, and disappear. Click them. The ship computer logs each successful capture with mild disapproval. Alien variants include decoys that cost O2 to examine.
Core loop: whack-a-mole variant. Click targets in ~1.5s windows before they vanish. Alien region: one decoy per session costs O2 if clicked. ~10 seconds total.
timing skill
First implementation step

6 target slots on a grid. Each slot activates for 1400ms at random, cycling through all slots over 10s. Click score → food yield. No decoys in v1. Display MARV commentary based on final score (≥5: "Acceptable." <3: "I had lower expectations. I was wrong.").

📡 Scan SCAN verb · deep space / nebula / anomaly
A signal blip wanders slowly on a circular radar screen. Drag the dish reticle to align with it and hold. Signal locks in 1.5 seconds of sustained alignment. Blip occasionally jumps. Anomaly region: blip moves erratically and screams.
Core loop: drag-to-align and hold. Alignment meter fills during overlap, drains when off. Lock = full meter held for 1.5s. One jump mid-session. ~10 seconds total.
spatial timing
First implementation step

Circular canvas, 300px. Blip = 12px circle wandering at 0.3px/frame on a curved path. Reticle = crosshair following cursor, clamped to disc area. Fill a progress bar when blip is inside a 24px radius of reticle. Win on bar full.

Forced Events — Crisis Resolution
💥 Patch Breach PATCH BREACH · FOAM IT verbs · hull breach event
A hull schematic appears with 3–5 breach points, each leaking atmosphere (animated particle stream). Click a breach then drag a patch panel to cover it. FOAM IT variant: hold mouse to spray foam in an arc across the crack outline — aim matters.
Core loop: click-select then drag-to-cover (Patch) or click-hold-draw (Foam). Atmosphere leak meter drains steadily. Seal all breaches before meter hits zero. ~12 seconds total.
spatial timing
First implementation step

3 static breach circles on a hull silhouette rect. Clicking one selects it (highlight ring). A patch panel appears; drag it onto the breach. Breach closes on overlap. No atmosphere meter yet — wire meter drain in v2.

⚡ Field Repair — Engine FIELD REPAIR verb · engine fault event
The drive coil diagram lights up 3–5 components in a sequence. You must click them in the correct order from memory. MARV recites the sequence once, deadpan, then refuses to repeat it. Wrong click = spark + partial damage.
Core loop: Simon Says sequence recall. Sequence shown for 2 seconds, then repeated by clicking labeled nodes. 3 wrong clicks = limp mode forced. ~15 seconds total.
pattern timing
First implementation step

5 labeled engine nodes in a fixed layout. Highlight sequence plays at 600ms per node (4-node sequence). Player then clicks in order. Track correct/incorrect clicks, flash node red on wrong. Display final result text. No damage stakes yet.

☀ Brace for Solar Flare BRACE FOR IMPACT verb · solar flare event
A shield integrity bar decays in real time. Hold the mouse button on a large BRACE button. Each second held costs morale but maintains the shield. Releasing drops shield integrity. Releasing early ends with significantly more hull damage.
Core loop: hold mouse to resist. Duration determines damage taken. Flare lasts 8–12 seconds. Visual feedback: screen pulses orange, shield flickers at low integrity. ~10 seconds total.
timing skill
First implementation step

One large button, mousedown starts timer, mouseup or timer expiry ends. Integrity bar fills on hold, depletes at 8px/sec when released. Flare timer: 10 seconds. Outcome = shield % held at flare expiry. Wire result text ("You held." / "You let go at 60%.").

Encounter Events
🎯 Combat pirate fight / bluff-called / ramming outcomes
Enemy ship occupies the encounter viewport. Targeting reticles drift toward it — click when aligned to fire. Enemy volley telegraphed by a glowing arc; move cursor off the arc zone to dodge. MARV provides running commentary that actively worsens morale.
Core loop: click to fire (reticle over target) + move cursor to dodge (off glowing arc zones). 3 volley rounds. Hit ratio + dodges avoided = outcome. ~15 seconds total.
timing spatial skill
First implementation step

Enemy ship = static rect center screen. One drifting reticle circle (auto-move, sinusoidal). Click when center is inside enemy rect = hit (flash). One telegraphed arc (orange zone, 1.5s warning). Cursor inside arc = hit taken. 3 rounds. Count hits/taken, display result.

🛸 Derelict Exploration ENGINE ROOM · CARGO BAY choices in derelict encounter
A pixel-art interior scene. Useful items (supplies, components) are partially hidden in clutter. Click them to claim. One hazard item (corroded container, crackling panel) is mixed in. Finding all items before the O2 timer empties is optional — but rewarding.
Core loop: click-to-find hidden object hunt. 4 useful items, 1 hazard. Hazard clicked = O2 cost. O2 drains regardless. Optional completion bonus. ~20 seconds total.
spatial skill
First implementation step

Static background rect representing a room. 4 "item" circles at fixed positions, visually styled as clutter details. Click highlights them. Track found count. No O2 timer or hazard in v1 — just the find-and-click loop with a score result at 20s.

Growbay & Ship Systems
🌾 Harvest mature crop · growbay screen
Mature pods glow along the plant's stems. Click each one to harvest it. Click too early and it pops (reduced yield). Click too late and it drops (lost). The ship computer rates your timing with the tone of someone who has seen better yields.
Core loop: rhythm / timing click. Each pod enters a "ready" window for ~1.2s. Click inside window = full yield. Before = early pop (50%). Missed = lost. 8–10 pods total. ~12 seconds.
timing skill
First implementation step

8 pod circles on a static plant silhouette. Each pod animates: gray → glowing → dark, staggered timers. Click during glow = full. Before = early. No click = dropped. Tally yield. Display MARV grade.

🔬 Plant Disease Diagnosis crop health critical · growbay alert
A plant silhouette appears with multiple clickable zones. Some zones show subtle discoloration or wilting. Click affected zones to identify them. Diagnosis determines which treatment item is requested from inventory.
Core loop: spot-the-difference identification. 2–3 affected zones among 6 total. Click a healthy zone = wrong (costs time). Identify all affected to unlock correct treatment. ~12 seconds total.
skill spatial
First implementation step

Plant SVG with 6 named clickable zones. 2 zones pre-marked "affected" in data. Clicking affected → green highlight. Clicking healthy → red. Win: both found without 3 wrong clicks.

💊 Medical Treatment crew health critical · derelict injury
A crew health panel shows 4 treatment supplies in random positions. The correct sequence must be clicked in order. Mix up the sequence and the treatment is ineffective but not dangerous — mostly just embarrassing.
Core loop: sequence recall with supply items as nodes. Sequence of 3 items shown for 2.5 seconds. Player must click correct order. 1 retry if wrong. Outcome scales with speed + accuracy. ~12 seconds total.
pattern timing
First implementation step

4 supply cards in fixed positions. Correct sequence highlighted at 700ms per card. Player clicks in sequence. Track correct/wrong. Single pass, no retry in v1. Outcome text keyed to perfect/partial/fail.

🏭 Fabricator Queue FAB verb · time-critical print jobs
The fabricator needs materials loaded into slots to start a print job. Drag resource icons from a tray into the correct recipe slots before the queue timer advances. Wrong material causes the fabricator LED to turn ominous amber.
Core loop: drag-match resource icons to labeled slots. 3–4 slot recipe. Wrong type bounces back. Queue timer pressure optional for non-critical jobs. ~15 seconds total.
spatial skill
First implementation step

3 recipe slots (labeled by resource type) and a tray of 5 icons (including 2 wrong types). Drag-drop: correct type snaps and locks, wrong type returns. All 3 correct = print job queued. No timer in v1.

Part 2 — Sprite Briefs

All sprites are PNG with transparent background unless marked bg (full-bleed jpg). Sizes are canvas dimensions at 1× — CSS handles scaling. Prepend the master prompt to every individual prompt.

Master style prompt

Prepend to all sprite prompts
16-bit pixel art, chunky hard-edged pixels, no anti-aliasing, no dithering except for deliberate retro texture, dark sci-fi color palette: void blue-black background #020408, deep slate #2a3040, warm gold accent #c8a85a, sage green #8cc890, signal orange #e88830, warm cream #e8d8a0 for highlights. 1-2px solid outlines on all objects. Transparent background unless specified. SNES era sprite quality. Style reference: FTL Faster Than Light, Terraria, early Stardew Valley. No gradients except hard 2-stop pixel dithering. Sprite canvas size specified per asset. --
Reuse check: Before generating new sprites, check demo-inventory, demo-growbay, and demo-cruise for existing resource icons and plant stage art — several are likely derivable from what already exists.
Mining
⛏ Mining bg MINE verb · asteroid / ice field
Sprite plan retired. The drift-and-click vein concept (ore_node / ore_node_rich / ore_hollow / mine_bg.jpg / dust_puff) was cut. The shipped mining mode (demo-mining.html) is a splitting-shooter that reuses the existing 81-asteroid grid in sprites/asteroids/ — no new asteroid art needed. Tiers (SMALL/STANDARD/LARGE/RICH/HOLLOW) are differentiated at runtime by size + brightness + a CSS sparkle for RICH and a CSS pulse for the wind-up before LARGE/RICH split. HOLLOWs are visually identical to LARGE until the player clicks them — that deception is the point. All particle effects (loot puff, hollow dust puff, flash ring, +N floater) are CSS-only, no spritesheets.
Backgrounds: sprites/minigames/mining/bg.jpg and bg{2..6}.jpg — 640×405. Painted inside the bridge viewport cutout (NOT full bleed). Stars-only / nebula-only is fine; the asteroid sprites layer on top.
Asteroids: sprites/asteroids/r{1..9}_c{1..9}.png — existing 81-sprite grid. No new asteroid art needed.
